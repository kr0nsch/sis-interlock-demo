# Демо-сценарий срабатывания ПАЗ в CODESYS Control Win

> **Внимание.** Код демонстрационный и не предназначен для систем безопасности. Реальная ПАЗ
> требует определения SIL, сертифицированных аппаратных и программных средств и валидации по
> ГОСТ Р МЭК 61511.

Отсюда берутся данные графика `docs/media/chart-trip-first-out-*.png` в README: короткий сценарий
идёт в настоящем рантайме CODESYS Control Win V3 в реальном времени задачи, а программа ПЛК пишет
трассировку, которую потом читает скрипт.

## Что выполняется

| Файл | Назначение |
|---|---|
| `st/POUs/PRG_TripDemo/` | сценарий: простая модель давления в V-101 задаёт токи PT101A/B/C и кнопку HS120, затем вызывается неизменённая `PRG_Sis` |
| `st/GVLs/GVL_TripTrace.gvl.st` | буфер трассировки: отсчёт каждые 100 мс, до 600 отсчётов |
| `trip_trace.py` | Python 3.11+: собирает демо-проект в `build/demo-trip/`, берёт блокировки `cds.py`, запускает CODESYS, пишет CSV |
| `cds_trace_step.py` | скрипт CODESYS (IronPython 2.7): шаг `trace` — вход в рантайм, старт, ожидание `xDone`, чтение буфера |

Демо-объекты в библиотеку и приложение не входят: `trip_trace.py` копирует `src/` в
`build/demo-trip/src/`, добавляет туда `st/` (папка проекта `Demo`), а задача `MainTask` (20 мс)
вызывает `PRG_TripDemo` вместо `PRG_Main`. Импорт и сборка — общими скриптами `tools/codesys`,
вход в рантайм — функциями `run_tests.py`, как у `cds.py test`.

## Сценарий (секунды от загрузки приложения, моменты — по отсчётам прогона 19.10.2026)

| t, с | Событие | Что делает логика ПАЗ |
|---:|---|---|
| 0 | старт ПЛК | все следствия в безопасном состоянии, первопричина «старт ПЛК» |
| 2 | кнопка HS120 | причин нет — сброс принят, выходы под напряжением |
| 6 | обрыв линии PT101C (2,0 мА) | канал недостоверен по NE 43; PSHH101 и PSLL101 (VoteTrip): 2oo3 → 1oo2 |
| 10 | давление растёт 0,04 МПа/с | — |
| 17,5 | PT101A ≥ 0,90 МПа | требование PSHH101, задержка 2 с |
| 19,6 | — | PSHH101: ESDV101 закрыт, H101 отключён, UA110 — сигнал; первопричина PSHH101 |
| после 19,6 | ESDV101 закрыт — давление падает (τ = 5 с) | требование PSHH101 снято, причина зафиксирована до сброса |
| 30,1 | PT101B ≤ 0,15 МПа | требование PSLL101, задержка 5 с |
| 35,2 | — | PSLL101: ESDV102, P101A, P101B; первопричина остаётся PSHH101 |
| 40 | кнопка HS120 | сброс отклонён: действует PSLL101 |
| 46 | конец записи | — |

Модель давления вымышленная и нужна только для того, чтобы входы менялись правдоподобно;
динамику объекта она не описывает.

## Запуск

```bat
python tools_project\demo\trip_trace.py --out docs\media\data\trip-trace.csv
```

Нужно то же окружение, что для `cds.py test` (CODESYS 3.5.17.30, библиотека PL, рантайм —
`docs/MANUAL_STEPS.md`). Прогон занимает около полутора минут: импорт и сборка, 46 с сценария,
чтение 461 отсчёта. Журналы — `build/demo-trip/import.log`, `build.log`, `trace.log`.

## Колонки CSV

| Колонка | Значение |
|---|---|
| `t_s` | время от первого цикла, с |
| `pt101a_mpa`, `pt101b_mpa` | давление модели у PT101A и PT101B, МПа |
| `pt101c_ma` | ток PT101C на входе ПАЗ, мА (2,0 — обрыв) |
| `arch_pshh101`, `arch_psll101` | действующая схема `E_VoteArch`: 23 — 2oo3, 12 — 1oo2 |
| `ch3_state_pshh101` | канал 3 группы PSHH101, `E_ChannelState`: 1 — норма, 3 — недостоверен |
| `cause_present`, `cause_active`, `cause_latched` | маски причин (бит 0 — PSHH101, бит 1 — PSLL101 …): требование, после задержки, зафиксирована |
| `effect_tripped` | маска сработавших следствий (бит 0 — ESDV101 … бит 6 — UA110) |
| `first_out`, `first_out_mask` | первопричина (65534 — старт ПЛК, 0 — нет, 1 — PSHH101) и причины в её цикле |
| `reset_permitted`, `reset_blocker` | сброс разрешён; первая мешающая причина |
| `hs120` | кнопка «Сброс ПАЗ» |
| `outputs` | выходы `xQ*` как биты: 1 — под напряжением |
